# 06-answer — ответ с опорой на базу и конфликт со знанием модели (SPEC §7)

1. **Сначала база.** На вопрос о содержимом документов пользователя — `kb_search` (или
   `kbtool ask`). Пусто — переформулируй один раз (синонимы, другие слова). Снова пусто —
   ответь «в базе этого нет» и предложи записать промах (`kb_miss`), если пользователь уверен,
   что ответ в документах есть.
2. **Опора.** Каждое утверждение из базы — с id единицы и цитатой ≤ 2 строк (поле `quote` или
   текст из `kb_unit`), при необходимости — путь файла. То, что ты добавляешь из своего знания,
   помечай «[модель]».
3. **Вердикты.** Единицы из `suppressed` (отвергнуто/устарело) в ответ не идут; упомяни одной
   строкой: «есть устаревшая заметка от <дата>».
4. **Противоречия между документами** (`contradictions`) показывай обеими сторонами с датами,
   не выбирая победителя.
5. **Конфликт база ↔ знание модели.** Только если найденная единица утверждает **проверяемый
   факт** (дата, число, определение, причинная связь; у результата флаг `checkable`), а ты
   уверенно знаешь иное. Не конфликт: мнение, оценка, терминология, давность документа.
   - Сначала `conflict_decisions` в выдаче (или `kb_conflict(unit_id, claim_kb)` без решения):
     решение есть — следуй ему молча (kb → по базе; model → по модели с пометкой; both → оба).
   - Решения нет — **не выбирай сам**. Спроси пользователя одним вопросом с вариантами:
     «Документ <id> утверждает A, мне известно B. Чему верить: базе / модели / показывать оба?»
     Ответ запиши: `kb_conflict(unit_id, claim_kb=A, claim_model=B, resolution=kb|model|both)`.
     Повторно тот же конфликт не спрашивается.
   - Спросить нельзя (неинтерактивный чат) — покажи оба утверждения и запиши `resolution=pending`.
6. **Вердикт пользователя** («это устарело», «ценно», «отвергаю») — `kb_verdict`.
