# CHANGELOG — kb-plugin

## 0.2.0 — путь новичка (не выпущен; ветка refactor/platform-only)
- Python ≥ 3.9: подходит `/usr/bin/python3` 3.9.6 из коробки Mac; `bin/kbtool` и `bin/kb-mcp` на старом Python объясняют по-русски, что поставить; тест синтаксиса 3.9.
- Новый скилл `/kb-start` («проверь плагин kb»): проверка Python (в т. ч. окно установки инструментов разработчика Apple), подключения инструментов kb, сборка демо-базы `~/.kb/kb-demo/` из трёх встроенных заметок `samples/`, вопрос с цитатами и противоречием, итог одной фразой.
- `/kb-build`: обязательное подтверждение перед разметкой моделью (`kbtool summary`: сколько файлов войдёт, объём, что исключено и почему; вопрос о лимите подписки; без «да» разметка не начинается).
- PDF без pypdf исключаются уже в описи с сообщением «PDF пока не читаются — пропущено N файлов: …» (до 10 имён); причины исключения — простыми словами (`excluded`, `notes` в scan/extract).
- `kbtool init --slug`: явное имя базы; демо-база переезжает на новый путь образцов после обновления плагина; `--corpus` находит базу с явным именем; демо-база не мешает выбору базы по умолчанию.
- Агенты в скиллах названы с префиксом плагина (`kb:kb-reader`, `kb:kb-tagger`); описание kb-tagger приведено в соответствие с тем, что он читает файл задания.
- Тест корпуса А привязан к коммиту `bc041da` репозитория strategy (47 заметок), извлекается `git archive` во временную папку; нет репозитория/коммита/разметки — skip с причиной.
